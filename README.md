# EasyTranslate - AI 驱动的双语阅读

一个类似沉浸式翻译的浏览器扩展，支持划词翻译和双语对照阅读。

## 功能特性

- 🎯 **划词翻译**：选中文本后点击浮动按钮，即时翻译
- 🔁 **双向翻译**：自动识别源语言，支持「英→中」阅读与「中→英」回复（Twitter / Reddit 等场景）
- ⌨️ **一键替换**：中→英模式下，选中的中文可直接被英文译文替换，按回车即发送
- 📖 **双语对照**：整页翻译，原文与译文段落对照显示
- 🤖 **AI 驱动**：支持 OpenAI 兼容 API（智谱 AI、OpenRouter、Groq、Ollama 等）
- 📝 **AI 音标**：由大模型直接生成 IPA 音标，覆盖生僻词、专有名词、品牌名
- 🔊 **朗读发音**：音标旁一键朗读（真人录音优先，系统 TTS 兜底）
- 📚 **生词本**：一键把译后的单词/短语加入生词本，支持搜索、导出 JSON/CSV
- 🧩 **批量补全**：历史词条缺失音标时，可一键用大模型批量补全
- 🎴 **每日复习**：生词本里的「今日新词」一键进入闪卡复习模式，自评「不认识 / 模糊 / 认识」后自动记录
- 🔒 **隐私安全**：API Key 本地存储，支持 HTTPS

## 技术栈

- Manifest V3
- TypeScript
- Shadow DOM + Web Components
- Vite 构建工具

## 安装使用

### 环境要求

- Node.js 18+
- Chromium 内核浏览器（Chrome、Edge、Arc 等）

### 1. 下载源码

```bash
git clone https://github.com/huangxinghui/easy-translate.git
cd easy-translate
```

### 2. 安装依赖

```bash
npm install
```

### 3. 构建插件

```bash
# 生产构建
npm run build

# 或开发模式（带热更新）
npm run dev
```

构建完成后，会在项目根目录生成 `dist/` 文件夹。

### 4. 加载到浏览器

#### Chrome / Edge

1. 打开浏览器，地址栏输入 `chrome://extensions/`（Edge 为 `edge://extensions/`）
2. 开启右上角「开发者模式」
3. 点击「加载已解压的扩展程序」
4. 选择项目中的 `dist` 目录

![加载扩展示意图](docs/install-step.png)

#### 加载成功标志

- 浏览器工具栏出现扩展图标（🌐）
- 点击图标弹出设置面板，说明加载成功

### 5. 配置翻译服务（首次使用必须）

1. 点击浏览器工具栏上的扩展图标 → 选择「打开设置」
2. 选择翻译服务提供商：
   - **哔哩哔哩 Index-Translate**（**免费、免密钥**，开箱即用）
   - **智谱AI**（国内大模型，中文优化好，**可生成音标**）
   - **自定义**（Ollama 本地部署或其他 OpenAI 兼容服务）
3. 填入对应的 API Key（哔哩哔哩无需填写）
4. 选择目标语言（默认：中文简体）
5. 点击「保存设置」

#### 可用的翻译服务

| 服务                      | 网址                            | 密钥 | 音标 | 特点                       |
| ------------------------- | ------------------------------- | ---- | ---- | -------------------------- |
| **哔哩哔哩 Index-Translate** | https://index-translate.bilibili.com | 免   | 间接 | 免费公网 API，150 种语言   |
| **智谱AI**                | https://open.bigmodel.cn         | 需要 | ✅   | `glm-4-flash` 免费额度充足   |
| **Ollama**                | http://localhost:11434           | 免   | ✅   | 本地运行，完全离线          |
| **OpenRouter**            | https://openrouter.ai            | 需要 | ✅   | 模型选择多，按需付费        |

> 💡 **音标能力说明**：通用大模型（智谱 / OpenAI / Ollama 等）能在翻译时一并给出 IPA 音标；专用翻译模型（Index-Translate）只输出译文，英文单词的音标改由词典补齐。两者发音都用真人录音优先、系统 TTS 兜底。

> ⚠️ **关于哔哩哔哩 Index-Translate**：它的 CDN 会拦截携带 `chrome-extension://` Origin 的请求（返回 412 挑战页）。扩展已通过 `declarativeNetRequest` 规则去掉该 header，行为与官方文档建议的「本地代理」方案一致。**如果遇到 HTTP 412，请到 `chrome://extensions` 刷新扩展**（新版会重新安装该规则）。

### 6. 开始使用

#### 划词翻译

1. 在任意网页上选中一段文本（≥1 个字符）
2. 选区附近会出现一个粉色浮动按钮（🌐）
3. 点击按钮，弹出翻译结果弹窗
4. 弹窗中可「复制译文」「交换」原文/译文，或「⭐ 加入生词本」保存词条

> 💡 点击页面空白处或按 `Esc` 可关闭弹窗

#### 用英文回复（Twitter / Reddit 等）

在聊天框里打中文 → 选中 → 翻译 → 直接替换成英文：

1. 在回复框里输入中文
2. 选中这段中文，浮动按钮出现，点击打开弹窗
3. 弹窗顶部会显示当前方向（`Auto` / `中→EN` / `EN→中`），可点击手动切换
4. 弹窗里显示英文译文，点「**替换选区**」按钮
5. 输入框里的中文被替换成英文，按回车即可发送

> 💡 「替换选区」按钮只在选中内容位于可编辑区域（`<input>` / `<textarea>` / `contenteditable`，如 Twitter、Slack、Discord 的输入框）时出现。方向为 `Auto` 时会根据源文本自动判断中/英。

#### 生词本

划词弹窗里的「加入生词本」按钮会把原文、译文、音标、来源 URL 一并保存到本地。再次选中同一文本时按钮会显示「✓ 已加入」，再次点击可移除。

打开扩展「设置」页面，最下方有**生词本**卡片：

- 顶部显示词条总数，支持关键词搜索（匹配原文、译文、笔记）
- 每条记录可单独删除，附带的音标按钮可以一键播放发音
- 一键导出为 **JSON** 或 **CSV**（可作为 Anki / 自定义生词本的导入源）
- 「清空生词本」按钮配合确认提示使用，避免误删

> 💡 词条 ID 根据「原文 + 目标语言」生成，重新翻译同一词条会更新译文，保留首次保存时间。

#### 音标与读音

音标与发音是**两层独立的能力**，引擎只影响前者：

| 能力 | 来源 | 覆盖 | 条件 |
| --- | --- | --- | --- |
| **音标文本**（IPA） | ① 通用大模型生成 → ② 词典 API 补齐 | 大模型几乎全覆盖；词典仅英文单词 | 选中的是单个单词 / 1-2 个汉字 |
| **发音声音** | ① 真人录音（词典） → ② 系统 TTS | 100%（系统 TTS 随时可用） | 无条件 |

也就是说：

- 用**智谱 / OpenAI / Ollama** 这类通用大模型 → 音标由模型生成，**生僻词、专有名词、品牌名、网络词都能拿到**
- 用**哔哩哔哩 Index-Translate** 这类专用翻译模型 → 引擎不生成音标，**英文单词的音标自动改由词典 API 补齐**（中文单词没有 IPA 来源，只有发音）
- 两种引擎的**喇叭按钮行为一致**：优先播真人录音，没有就用系统语音合成

- **划词弹窗**：音标右侧的喇叭按钮一键朗读
- **生词本列表**：每条记录的音标行右侧有一个醒目的播放按钮，点击听发音（按钮会在播放时高亮）
- **复习模式**：原文旁边独立加了一个圆形播放按钮，不需要先点「显示答案」就能听；加载新题时还会自动播一次，帮助你先听音回忆
- **批量补全**：生词本里早期保存的词条若没有音标，顶部会出现提示条，点「一键补全」用大模型批量补上

> 💡 只有单词（支持连字符 / 撇号如 `self-esteem`、`don't`）和 1-2 个汉字才会显示音标与喇叭。整句、整段、多行文本不显示，避免噪音。

生词本卡片顶部会出现“今日新词 N 个 [开始复习]”的金色横幅（只包含本地日期下创建的词条）。点击按钮进入闪卡模式：

1. 先看到词条的**原文**（大字体居中），「显示答案」按钮可以揭晓译文 + 音标 + 来源
2. 点下方三档自评中的一个进入下一题：
   - **不认识**（红）：今天第一次接触，需多加复习
   - **模糊**（黄）：有印象但不熟，下次再来看
   - **认识**（绿）：完全掌握
3. 答完本轮后显示「本轮总数 / 认识 / 模糊 / 不认识」总结，可以「再来一轮」反复刷，或「返回生词本」

每次自评会在词条上记录 `lastReviewedAt` 和 `reviewCount`，不引入复杂的间隔重复算法。

> 💡 词条即使复习多轮也不会从“今日”队列里移除——欢迎反复刷加深记忆。

#### 整页双语翻译

1. 打开任意有可读内容的网页
2. 按快捷键 `Alt + T`，或点击扩展图标选择「翻译页面」
3. 页面每段原文下方会插入对应的译文段落
4. 再次按 `Alt + T` 可恢复原始页面

> 💡 翻译过程中按 `Esc` 可取消

## 常见问题

**Q：为什么翻译 Twitter/X 页面提示「页面没有可翻译的内容」？**

A：Twitter/X 的推文文本使用 `div` 标签包裹，旧版提取器将其视为容器而跳过。已在 [d026cad](https://github.com/huangxinghui/easy-translate/commit/d026cad) 修复，支持通过 `data-testid="tweetText"` 等平台标记识别 div 文本容器。

**Q：插件在某些页面报错 "The provided markup is invalid XML"？**

A：XHTML 文档要求 `innerHTML` 传入良构 XML。已在 [d026cad](https://github.com/huangxinghui/easy-translate/commit/d026cad) 修复，将所有 `<img>`、`<br>` 等空元素改为自闭合形式。

**Q：支持 Firefox / Safari 吗？**

A：当前仅支持 Chromium 内核浏览器（Chrome、Edge、Brave、Arc 等）。Firefox 需要额外适配 Manifest V2/MV3 差异，计划后续支持。

**Q：用了哔哩哔哩 Index-Translate 报 HTTP 412 怎么办？**

A：该服务的 CDN 会拦截携带 `chrome-extension://` Origin 的请求。扩展已通过 `declarativeNetRequest` 规则移除该 header（与官方文档建议的本地代理方案一致）。若仍报 412，请到 `chrome://extensions` 刷新扩展以重新安装规则。

## 权限说明

| 权限 | 用途 |
| --- | --- |
| `storage` | 本地保存 API Key、翻译缓存、生词本、复习记录 |
| `activeTab` | 仅在用户主动划词时向当前页面注入内容脚本 |
| `scripting` | 按需注入内容脚本（页面未加载扩展时） |
| `tts` | 朗读单词发音，使用浏览器/系统语音引擎，不联网 |
| `declarativeNetRequestWithHostAccess` | 仅对哔哩哔哩翻译接口移除 `Origin` 请求头（其 CDN 会拦截扩展来源）。规则只作用于本扩展发起、指向该单一域名的 POST 请求 |
| `<all_urls>` | 划词翻译需在任意网页监听文本选区 |

**隐私**：所有翻译请求（原文与译文）只发往你在设置中配置的 API 服务地址；扩展自身不收集、不上传任何数据。
